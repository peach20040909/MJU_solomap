# SoloMap 검증 기록

**2026-11-09 갱신:** 전용 Supabase DB 연결·마이그레이션·식당 125곳 시드 및 실제 가입/인증/리뷰 CRUD/체크인/프로세스 재시작 후 세션 유지 검증을 완료했습니다. [최신 실제 DB 연결 기록](SUPABASE_CONNECTION.md). 로컬 Gmail SMTP 설정과 TLS/계정 인증 확인도 완료했으며 실제 학교 메일 수신 확인만 남아 있습니다. 아래 2026-11-06 내용은 연결 전의 검증 이력이며 현재 DB 미연결 상태를 뜻하지 않습니다.

확인일: 2026-11-06 (Asia/Seoul). 대상은 현재 로컬 작업 파일이며 공개 서비스에 배포한 결과가 아닙니다.

## 환경과 실행 방법

`DATABASE_URL`, `DIRECT_URL`, `SESSION_SECRET`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`이 현재 로컬 환경에 없습니다. 비밀값 자체는 조회 결과나 이 문서에 기록하지 않았습니다.

```bash
npx tsx scripts/verify_api.ts
node scripts/test_account_ui.cjs
npm run typecheck
npm run build
```

첫 번째 스크립트는 실제 Express 앱을 임시 포트로 실행합니다. 쿠키를 보내지 않으며 DB 쓰기를 하지 않습니다. 두 번째 스크립트는 실제 HTML/CSS/JS를 Chrome에서 실행하지만 API와 네이버 지도 SDK 경계에는 테스트 응답을 사용합니다. 화면 테스트 통과는 실제 DB·SMTP·지도 인증 성공을 의미하지 않습니다.

## DB·메일 통합 검증 대기

아래의 실제 응답은 아직 얻지 못했습니다. 예상 상태 코드를 실행 결과로 대신 적지 않았습니다. `requests.http`에 모든 요청이 준비되어 있습니다.

| 요청 ID | 시나리오 | 기대 | 실제 / 이유 |
|---|---|---|---|
| P04 | DB 식당 목록 | 200 | 미실행 / DB 연결 필요 |
| A07 | 학교 계정 생성·코드 발송 | 201 | 미실행 / DB·메일 설정 필요 |
| A08~A09 | 이메일·닉네임 중복 | 409 | 미실행 / 기존 계정 필요 |
| A10~A12 | 잘못된 비밀번호·정상 로그인·내 정보 | 401 / 200 | 미실행 / DB 계정·세션 필요 |
| A13~A14 | 미인증 학우의 리뷰·체크인 | 403 | 미실행 / 미인증 로그인 세션 필요 |
| A15~A16 | 60초 재발송 제한·정상 재발송 | 429 / 200 | 미실행 / 코드·세션 필요 |
| A17~A20 | 코드 형식·오입력·횟수 초과·만료·인증 성공 | 400 / 200 | 미실행 / 인증 기록 필요 |
| R01~R03 | 잘못된 리뷰·없는 식당 | 400 / 404 | 미실행 / 인증 사용자 필요 |
| R04~R08 | 리뷰 생성·중복·내 목록·수정·평균 갱신 | 201 / 409 / 200 | 미실행 / DB 필요 |
| R09 | 없는 리뷰 수정 | 404 | 미실행 / 인증 사용자 필요 |
| C01~C03 | 없는 식당·정상 체크인·당일 중복 | 404 / 201 / 409 | 미실행 / DB·인증 사용자 필요 |
| C04~C06 | 레벨·정복 목록·추천 | 200 | 미실행 / DB 방문 기록 필요 |
| B04~B05 | 인증 B가 인증 A의 리뷰 수정·삭제 | 403 | 미실행 / 인증된 두 계정 필요 |
| Z03~Z05 | 리뷰 삭제·없는 리뷰 재삭제·평균 초기화 | 204 / 404 / 200 | 미실행 / DB 리뷰 필요 |
| Z06~Z07 | DB 세션 파기·쿠키 재사용 차단 | 204 / 401 | 미실행 / 실제 로그인 쿠키 필요 |

확인 순서:

1. 개발용 DB와 세션 키를 설정하고 테이블·식당 시드를 준비합니다.
2. REST Client의 쿠키 저장/전송을 켜고 `requests.http`의 A00부터 진행합니다. 가입만으로 로그인되지는 않습니다.
3. 소유한 테스트 학교 계정 A로 가입·로그인합니다. 인증 전 403을 확인한 뒤 코드를 입력합니다. 재발송 성공은 마지막 발송 후 60초가 지난 다음 실행합니다.
4. A로 리뷰·체크인을 검증합니다. 체크인의 `levelAtVisit`은 그 요청 직전 서버 표시 난이도와 비교합니다.
5. 두 번째 학교 계정 B를 인증한 후 A 리뷰에 대한 403을 검증합니다. B가 미인증이면 소유권 검사 전 인증 미들웨어에서 차단되므로 소유권 검증이 아닙니다.
6. A로 재로그인해 리뷰를 삭제합니다. 다른 리뷰가 없다면 DB `avgSoloLevel=null`, `reviewCount=0`과 상세 응답 `rawAvg=null`을 확인합니다.
7. 계정·체크인은 현재 삭제 API가 없습니다. 테스트 DB에 기록이 남으며 같은 식당 당일 체크인 재실행은 409가 정상입니다. 운영 DB를 초기화하지 않습니다.
8. 실제 결과를 위 표에 갱신합니다. DB가 없는 리뷰 조회의 빈 배열 폴백을 저장소 연결 성공으로 간주하지 않습니다.

## 운영 전 보완 후속 검증

`npx tsx scripts/test_production.ts`에서 10개 시나리오와 상위 테스트를 포함한 **11/11 통과**를 확인했습니다. 수정 전에는 운영 설정 누락 허용·코드 로그·SMTP 실패 성공 처리·실패 기록 정리가 실제로 실패했습니다.

- 운영 필수 설정 누락 시 앱 시작 거부, Vercel Preview도 같은 검사 적용.
- 설정 정상 허용, 32자 미만 세션 키·잘못된 SMTP 포트·잘못된 DB URL 거부.
- 로컬 SMTP 서버의 정상 수신, 거절 응답 503, 운영 코드 로그 없음.
- 가입 메일 실패 시 새 계정/코드 정리, 재발송 실패 시 이전 코드 보존·실패 코드 제거·즉시 재시도.
- SMTP가 완전히 미설정된 로컬에서만 콘솔 코드 허용, 부분 설정 오류는 503.
- 실제 Express 가입 경로에서도 SMTP 거절 시 `{ message }` 503과 실패 계정 정리를 확인.

SMTP는 로컬 TCP 서버이며 외부 학교 메일을 보내지 않았습니다. 서비스 실패 복구는 DB가 없어 Prisma 입출력 경계만 메모리 저장소로 대체했습니다. 실제 PostgreSQL FK Cascade·세션·메일함 수신 검증은 여전히 남아 있습니다. 사용자는 별도 SoloMap Supabase 프로젝트를 사용할 예정이며 연결된 다른 프로젝트는 변경하지 않았습니다.

## 배포 전 남은 항목

- 실제 DB·SMTP 설정과 위 통합 검증 표를 완료해야 합니다. 세션은 DB 스토어로 유지되는지 HTTPS 배포 환경에서 확인합니다.
- 운영 코드 로그·발송 실패 성공 처리는 후속 수정과 로컬 SMTP 검증을 마쳤습니다. 실제 SMTP 제공자와 학교 메일함 전달을 확인해야 합니다.
- 운영/Preview는 필수 환경변수 누락 시 시작을 거부하도록 수정했습니다. 실제 배포의 DB 세션 지속성과 HTTPS 쿠키를 확인해야 합니다.
- 이전 단계 실제 화면에서 네이버 지도 인증 실패가 관찰되었습니다. 이번 SDK 대체 테스트로 해결된 것으로 간주하지 않습니다. 네이버 Client ID·등록 도메인을 실제 배포 주소와 맞춘 뒤 확인합니다.
- [README의 Vercel 체크리스트](../README.md#vercel-배포-체크리스트)는 확인 목록입니다. 체크되지 않은 항목을 완료 기능으로 발표하지 않습니다.
