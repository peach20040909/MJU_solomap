# 디자인 시스템 1.2 · 2026-11-09

사용자가 선택한 기준은 “네이버 지도처럼 간결하고 실용적”이다. 버튼/칩/카드를 동일한 테두리 형태로 쓰던 문제를 역할별 스타일로 구분했다. 검색 제목 24~28px/700, 점무늬 제거, 평면 난이도 범례, 중립색 보조 작업, 텍스트 메뉴, 검정 선택 필터, 흰 배경과 진한 하단선의 선택 보기 전환을 적용했다. 기능·라우트·DB는 수정하지 않았다.

UI/UX Pro Max quick-reference의 단일 주요 액션·일관된 위계·색 대비·터치 규칙을 참고했다. targeted 검색 2회는 각각 Hover/Breadcrumb 및 Back Button 등으로 반환되어 버튼 위계에 맞는 검증된 결과를 찾지 못했으므로 해당 검색 결과는 적용하지 않았다.

독립 검토에서 중요한 기능 회귀는 발견하지 못했다. 선택 보기의 흰 배경만으로는 구분이 약하다는 지적에 따라 진한 2px 하단선을 더했다.

실제 공통 CSS를 쓰는 갤러리에 작업/메뉴/보기 전환의 역할별 예시를 추가하고 타이포그래피 설명을 구현과 맞췄다. 실제 화면과 갤러리 모두 375/768/1024/1440px·글자 200%·터치·대비·모션 감소·모달 키보드 검사를 통과했다. 주요 액션 대비는 4.93:1, hover 6.54:1이며, 기존 계정·리뷰·체크인·지도 회귀 및 typecheck/build도 통과했다.

# 2026-11-09 개정

사용자 피드백에 따라 초기 딥블루 스타일을 종료하고 기존 오렌지·중앙 검색 구성을 복원했다. 큰 성장 소개 패널을 기록 스트립으로 줄였다. 공통 폰트·버튼·입력·간격·키보드 동작은 유지했다. UI/UX Pro Max의 targeted UX 검색과 실제 화면 검사를 사용했으며, 검색 결과 중 제목 줄 균형 지침만 관련 항목으로 적용했다.

375/768/1024/1440px, 글자 200%, 대비·터치·모션 감소·모달 키보드 검사와 기존 계정/리뷰/체크인/지도 회귀가 통과했다. 로그인 직후 프로필 응답으로 헤더가 교체되는 테스트 타이밍 문제는 Puppeteer locator 클릭으로 보완했다.

# SoloMap 디자인 시스템 검수

2026-11-06 · 사용자 요청: 재사용 가능한 DS, PC/모바일 위계·폰트·컬러·반복 컴포넌트. 사용자 선택: 딥블루.

## 사용한 스킬과 적용 판단

[UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)의 `.claude/skills/ui-ux-pro-max`를 Codex 스킬로 설치하고 SKILL.md, quick-reference, pro-rules를 읽었습니다. 이 도구는 권고를 검색하며 실제 화면의 자동 합격 판정기는 아닙니다. 결과를 제품에 맞춰 판단하고 브라우저 측정·렌더링으로 검증했습니다.

| 실행 검색 | 확인 결과 | 적용 |
|---|---|---|
| `restaurant discovery warm minimal --design-system` | 미니멀 그리드, 절제된 효과, 타입 위계. 영문 레스토랑 랜딩 패턴·빨강/골드·Playfair/Karla 추천 포함 | 그리드/효과 원칙 채택. 한글 탐색 도구와 사용자 선택에 맞춰 Pretendard·딥블루로 구성 |
| `university education blue --domain color` | LMS 틸(적합도 낮음), Research Lab/University Department 네이비(적합) | 대학 분위기 네이비 방향 참고, 액션 블루와 뉴트럴 별도 정의 |
| `touch target minimum spacing --domain ux` | 웹의 WCAG 최소 타깃과 네이티브 기준을 구분, 인접 타깃 8px 간격 | 제품의 사용성 기준으로 44px 버튼/48px 입력, 8px 이상 간격 |
| `body font line height hierarchy --domain ux` | 모듈러 타입, 본문 1.5~1.75, 명확한 텍스트 대비 | 12/14/16/20/24/32/40 위계, 본문 1.6 |
| `focus not obscured keyboard modal --domain ux` | visible focus, sticky 요소에 가려지지 않는 포커스 | 3px 포커스 링, scroll-padding, 모달 순환·복원 |

Tailwind/React를 사용하지 않는 프로젝트이므로 해당 프레임워크 권고는 적용하지 않았습니다. 웹에 native pt/dp 기준을 그대로 합격 조건으로 주장하지 않았습니다.

## 구조와 실제 적용

- `design-system.css`: 의미 기반 토큰, 공통 버튼/입력/필드/배지/표면/피드백/빈 상태/모션.
- `style.css`: 중복되던 화면 스타일을 정리한 앱 레이아웃.
- `map.css`: 기존 지도 엔진 규칙을 분리하고 DS 컨트롤 어댑터 적용.
- `ui.js`: 같은 SVG 패밀리, 모달 키보드·배경 스크롤, 선택 상태 접근성.
- 실제 헤더·검색·필터·식당 카드·리뷰·로그인·성장 화면의 정적/동적 마크업에 공통 클래스 적용.
- `design-system.html`: 실제 CSS를 공유하는 버튼 상태·폰트·컬러·입력·카드 미리보기.
- Pretendard를 자체 호스팅하고 OFL 라이선스 포함. 외부 폰트 CDN 요청 제거.

## 발견하고 수정한 문제

1. 375px에서 200% 글자 확대 시 검색 입력과 버튼이 겹침 → 모바일 검색 입력/CTA 세로 배치.
2. 지도 외부 링크가 카드 내 일반 링크로 남아 작은 타깃이 됨 → 링크도 공통 버튼 클래스로 연결.
3. 기존 모달의 배경 포커스 이동·복원 부재 → 공통 키보드 처리 추가.
4. 본문 줄바꿈을 모바일에서 숨기면서 단어가 붙음 → 줄바꿈 뒤 실제 공백 유지.
5. CSS 중복·11px대 텍스트·팔레트별 임의 버튼 → 토큰·컴포넌트·지도 어댑터 분리.

## 확인 범위와 남은 환경 의존성

스크린샷은 로컬 테스트 데이터로 렌더링하여 확인했습니다. 브라우저 테스트의 API·지도 SDK 경계는 fixture이며 실제 지도 타일/제공자 인증 검증이 아닙니다. 실제 DB·SMTP 설정이 없어 저장·메일 전달 검증도 별도입니다. 다크 모드는 이번 사용자 범위에 포함하지 않았습니다. 기존 로고와 레벨 칭호의 의미 있는 이모지는 유지하며, 주요 구조 아이콘은 SVG로 통일했습니다.
